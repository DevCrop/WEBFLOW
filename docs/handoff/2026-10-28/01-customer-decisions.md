# 고객 요청과 최종 합의

메일, 고객이 대화에 붙인 요청, 이후 사용자 수정 지시를 대조한 작업용 요약이다. 인용 메일의 모든 문장을 현재 구현 완료 사실로 해석하지 않는다.

## 산출물 7-1~7-6

| 항목 | 필요한 산출물 | 완료 판정 기준 |
|---|---|---|
| 7-1 사이트 | Webflow 사이트 산출물 | 실제 프로젝트 접근·보관 방식 확인 |
| 7-2 디자인 | Figma 원본 / 협의한 .fig 전달 | 파일 전달 또는 소유권 이전을 실제 확인 |
| 7-3 스타일 정의 | 컬러·폰트·컴포넌트·에셋 | 현재 Figma VOLUME 01 및 PDF 검수 |
| 7-4 기능·인수인계 | CMS·다국어·코드·외부 연동·에셋 | VOLUME 03과 실제 설정의 연결 |

| 7-6 운영 교육 | 같은 PDF로 관리자 화면 안내 | 실제 교육 후 일시·참석·실습 결과 기록 |

Webflow 백업 전달 메일은 **현재 계정의 운영 프로젝트·도메인·구독을 유지하고, 복제본을 별도 회사 계정/Workspace에 보관**하는 구분이었다. 복제본 전달 완료 여부는 별도 증거가 필요하다. 복제본이 폼 제출 이력·알림·다국어 활성화까지 운영 환경과 같다는 표현은 금지한다.

사용자는 문서에서 도메인·서버 관리 같은 불필요한 책임 범위 확대를 원하지 않는다. Private Resources는 논의 후 작성할 자리만 유지한다. 계정 결제·법적 검토·광고 운영을 개발사가 상시 수행한다고 쓰지 않는다.

## 리포트 흐름의 최종 결정

초기 별도 다운로드 페이지 방식 이후, **뉴스룸 글 VIEW → 본문 리포트 버튼 → 같은 화면의 모달 → 정상 접수 → 제자리 PDF 다운로드**로 발전했다. 별도 브라우저 창 팝업이 아니다. 예전 성공 카드나 다운로드 HTML 페이지로 이동하는 설명으로 되돌리지 않는다.

- 버튼: KR **리포트 다운로드**, EN **Download Report**.
- 안내: KR **아래 정보를 입력한 후 다운로드 버튼을 누르시면 리포트를 받으실 수 있습니다.**
- EN: **Please fill out the form below to download the report.**
- PC는 왼쪽 세로형 리포트 이미지 / 오른쪽 폼. 모바일은 이미지 없이 폼만.
- 기존 입력·폰트·버튼 컴포넌트 재사용. CTA 전체 너비, 라운드는 작게.
- 중앙 정렬·backdrop·배경 스크롤 잠금·모달 내부 스크롤·SVG 닫기·포커스 복귀.
- Webflow 네이티브 검증과 성공 신호를 유지. 유효하지 않은 제출에는 PDF 제공하지 않음.
- 접수 중/다운로드 중 버튼 상태. 접수 성공 후 다운로드 재시도는 접수·메일을 다시 보내지 않도록 구분.
- 이름·회사·부서·직책·이메일 필수. 연락처·문의 내용·광고 수신 동의 선택. 개인정보 수집·이용 동의 필수.
- 국영문 모두 관리자 알림 수신처는 **info@intellectualdata.com**.
- 접수 언어 KO/EN, 접수 페이지 URL을 숨김 필드로 포함. 쿼리/해시는 제외.
- 뉴스룸 제목: KR [자료] 리포트명 / EN [Research] 리포트명. 제목 뒤 회사명은 사이트 정책과 중복되지 않게 관리.
- 국영문 최종 PDF·썸네일은 고객 최신 자료 기준. 초기 테스트 PDF·구버전 자산으로 되돌리지 않음.
- 공지 배너 전체 영역 클릭. 배너를 내려도 글·직접 PDF 링크가 자동 비공개가 되는 것은 아님.
- 새 리포트는 CMS 복제만으로 동작하지 않는다. slug·폼 이름·이미지·PDF·코드 대상 연결 검수가 필요.

## 마케팅 관련 합의

고객은 GTM에서 GA와 광고 태그를 일괄 관리하고 직접 설치 GA 중복을 피하기를 요청했다. 운영 매체는 네이버·Meta·LinkedIn·Google Ads. 고객은 **GA 주요 이벤트 지정과 Google Ads 전환 등록은 계정에서 직접 진행**한다고 밝혔다.

요청 이벤트는 국영문 공통 3개:
1. `contactus_form_submit`: 문의 정상 제출 완료.
2. `contactus_page_view`: 문의 페이지 도달.
3. `newsletter_form_submit`: 뉴스레터 정상 신청 완료.

쿠키 미선택/거절·분석만·광고만·모두 허용의 차이, 저장 단위·기간·철회 동작을 가이드에 요구했다. 실제 매체 계정의 집계와 사이트 실행 증거는 구분한다.

추가 전환(자료 다운로드 등)의 **추가 방법 안내**도 메일상 약속이다. 현재 리포트 전용 이벤트는 설치 3종에 포함되지 않는다. 최종 PDF에서는 신규 이벤트를 이미 적용했다고 쓰지 말고, 발생 조건·dataLayer·GTM 트리거·동의·미리보기·계정 확인의 추가 절차를 설명할 필요가 있다.

## 게시판 요청 11항목

1. Featured는 직접 지정, 지정 글 중 최신 날짜순 최대 3개.
2. 이관 글의 숫자 slug 유지 / 신규는 식별 가능한 영문 slug. 언어 대응과 중복 확인.
3. 페이지 title suffix: KR 인텔렉추얼데이터 / EN Intellectual Data. CMS 제목에 중복 수동 입력하지 않음.
4. 상세 본문 최대 880px, 모바일 화면 대응.
5. Newsroom·Insights 상세 상단 썸네일 숨김. 목록 썸네일 유지.
6. 상세 요약 중복 표시 숨김, 선택 입력. Release Notes 목록 요약 용도는 유지.
7. 텍스트 잘림·글별 문단 간격 검사. 전체 저장 본문 검사와 실제 렌더 표본을 구분.
8. 본문 이미지는 본문 너비를 넘지 않게. 작은 그림은 필요시 여백 포함.
9. 이전/다음 추천 대신 목록 복귀, 목록 진입 정보가 있으면 페이지 유지.
10. 본문 마지막과 목록 버튼 사이 여백.
11. 미운영 영문 Insights·Release Notes는 직접 URL도 영문 홈으로 이동.

최종 사이트 판정은 메일 문구가 아니라 가장 최근 검수 근거를 따른다.
